DECISIONES Y NOTAS TECNICAS IMPORTANTES
---------------------------------------
- ES MODULES PROHIBIDOS aqui: file:// los bloquea. Todo es <script src> clasico
  con patron (function(global){ ... global.tm.X = ... })(window).
- ORDEN DE CARGA en index.html IMPORTA (scripts sincronicos):
    utils(roles,nav,router,data,draft,fixtures) -> components(layout,button,
    field,table,stepper,timeline,modal,errors,verified-field,file-upload,
    signature) -> utils/wizard -> services/session -> fixtures(p-06..p-18)
    -> views(p-01..p-27) -> app.js
  Al agregar vistas nuevas: anadir su <script>, su bloque de fixtures y su rama
  en js/app.js (key === "p-XX") pasando wizardOpts = { onNavigate: navigate }.
- El router (js/utils/router.js) tiene un map ruta->clave de vista. Las rutas del
  asistente (#/solicitud/*) se validan con mapHas() aunque no esten en el menu.
- Acceso: solo rol SOLICITANTE en el portal; resto de roles -> modulo interno.
- Sin credenciales/secretos; todo dato es ficticio; OTP/MFA/firma/pago/QR simulados.
- Campos origen "A": se muestran sellados y bloqueados (components/verified-field.js).
- El esquema oficial de mocks HU-08 AUN NO esta publicado: se uso un sobre
  provisional { meta, data, error } (ver Frontend/js/fixtures/README.md). Como
  fetch()/JSON esta bloqueado en file://, el loader js/utils/fixtures.js registra
  cada envelope desde un <script src> (js/fixtures/*.js) con la MISMA nomenclatura
  y esquema; load() sirve el mismo envelope como .json cuando haya servidor.
