# QA – Sprint 3: Review y flujo principal

## Objetivo

Validar el incremento presentado en el Review: navegación real, expedientes, documentos, permisos, estados y trazabilidad de las acciones.

## Actividades de QA

1. Crear un expediente con datos ficticios válidos.
2. Rechazar datos inválidos y verificar mensajes seguros.
3. Confirmar que un usuario no puede consultar expedientes ajenos.
4. Asociar documentos permitidos y rechazar tipos o tamaños no permitidos.
5. Verificar descargas según el rol.
6. Revisar observaciones, cambios de estado, historial y auditoría.

## Evidencias esperadas

- Recorrido funcional grabado o capturado.
- Casos de prueba ejecutados.
- Resultados de autorización.
- Evidencia de documentos rechazados y aceptados.
- Reporte de defectos y correcciones.
- Métricas de casos ejecutados, defectos y cobertura.

## Criterio de cierre

El flujo principal debe ser reproducible, los permisos deben respetarse, los documentos deben estar protegidos y las operaciones críticas deben quedar auditadas sin datos sensibles en los logs.

## Estado

Alcance de validación preparado para la demostración del incremento. Los resultados deben mantenerse junto con sus evidencias.
