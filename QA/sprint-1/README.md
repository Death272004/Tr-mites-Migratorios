# QA – Sprint 1: Avance de desarrollo y correcciones

## Objetivo

Convertir la estrategia inicial en casos de prueba verificables y revisar que los primeros prototipos, mocks y contratos permitan avanzar sin bloqueos de integración.

## Actividades de QA

1. Revisar las correcciones aplicadas al análisis y al backlog del Sprint 0.
2. Preparar el plan de pruebas por historia de usuario.
3. Verificar contratos de las fuentes simuladas de Tribunal Electoral, CSS, Registro Público y Migración.
4. Recorrer el flujo inicial con datos ficticios.
5. Registrar defectos con severidad, evidencia, responsable y estado.

## Casos iniciales

- Respuesta válida de una fuente simulada.
- Fuente sin resultado.
- Error técnico o tiempo de espera.
- Datos inválidos en formularios.
- Acceso no autorizado.
- Respuesta de API con código de error.

## Evidencias esperadas

- Plan de pruebas publicado.
- Matriz historia–caso de prueba.
- Resultados de contratos de mocks.
- Capturas o respuestas de API.
- Registro de incidencias.

## Criterio de cierre

Los contratos críticos deben estar verificados, el recorrido inicial debe ser reproducible y todo bloqueo debe quedar registrado formalmente.

## Estado

Base de pruebas definida; los resultados deben completarse con la ejecución del equipo sobre el entorno integrado.
